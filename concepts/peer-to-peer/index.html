    Core Concepts

    Peer-to-peer fundraising#

    A supporter can spin up their own fundraising page — individually or as part of a team — under a parent campaign, and donations made through it attribute back automatically.

    Fundraising pages and teams#

    Object Represents
    Fundraising_Page__c One supporter's personal fundraising page — their own goal, story, and progress, nested under a parent Campaign
    Fundraising_Team__c A group of Fundraising_Page__c records rolled up into a shared team goal

    A supporter creates their own page through a public, guest-accessible signup flow — there's no staff step required to launch a new fundraiser once a campaign is open for peer-to-peer.

    How attribution works#

    Donations made through a supporter's page still go through the exact same donation pipeline as any other gift — the same staging record, the same Stripe confirmation, the same Opportunity creation. What's different is what happens after the Opportunity is finalized: DonationFinalized__e, an internal platform event fired after the finalize transaction commits, is picked up by DonationFinalizedSubscriber, which runs P2PAttributionService to credit the gift back to the correct Fundraising_Page__c and Fundraising_Team__c.

    This is a deliberate decoupling: the core donation-finalize path doesn't need to know peer-to-peer attribution exists, and attribution logic doesn't run inline inside the payment confirmation transaction.

    Why a platform event, not a direct call

    Peer-to-peer fundraising was originally planned as a separate extension package layered on top of a base donation package — the platform event was the sanctioned way for an extension to react to something happening in the base package without a compile-time dependency. The two were merged into a single package on 2026-07-13 because P2P's features turned out to depend too closely on base Campaign functionality to stay cleanly separated. The platform event remains as an internal implementation choice — it's a clean seam, not a packaging requirement anymore.

    Public pages#

    Each fundraising page and team has its own public, guest-accessible URL — donors browsing to a supporter's personal page see their story, their progress toward their individual goal, and a donation form scoped to that page (which still rolls up to the parent campaign).

    Requires its own Experience Cloud pages

    Peer-to-peer runs on three dedicated Experience Cloud pages (Fundraiser Page, Team Page, Fundraiser Sign-Up) — they aren't part of the shared donation-page component and won't exist until you build them. See Set up your Experience Cloud site.
