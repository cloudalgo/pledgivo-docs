    Core Concepts

    Events & ticketing#

    A ticketed event is still a Campaign underneath. Tickets are line items, seats are reserved before payment, and the same staging-and-reconcile pipeline finalizes the purchase.

    What donors see#

    **What it shows.** A live public event page — hero with an EVENT FUNDRAISER badge, a date/venue/seats-left stat bar, an "Our story" section, and a 4-step wizard (Tickets → Attendees → Your info → Payment) with per-tier pricing, tax-deductible amounts, and a remaining-seats badge on each tier.

    Same pipeline, different payload#

    Event ticket purchases don't get a separate payment system — they go through the identical Donation_Staging__c → Stripe → reconcile flow described in Donations & payments. What's different is the Purchase_Type__c discriminator on the staging record: a value of Event_Ticket routes finalization to EventPurchaseService instead of the plain donation finalizer, which creates the Opportunity plus OpportunityLineItem rows (one per ticket tier purchased) and an Event_Attendee__c record per seat.

    Seats are reserved before the charge completes#

    EventRegistrationController.createTicketIntent increments Quantity_Sold__c on the ticket tier — under a row lock (FOR UPDATE) so two donors buying the last seat can't both succeed — before the Stripe PaymentIntent is confirmed. This trades a small risk (a seat held by an abandoned checkout) for the alternative, which is worse: two people paying for the same last seat because reservation happened only after payment.

    That risk is bounded by a short staging expiry: an event's Donation_Staging__c row expires after 30 minutes (compared to 72 hours for an ordinary donation), and an expired or canceled staging row releases its held seats back to inventory via releaseReservation.

    Refunds and seats#

    Refund type Effect on the seat
    Full refund Seat is released back to inventory (EventPurchaseService.releaseForOpportunity)
    Partial refund Seat is not released — a partial refund is assumed to be a price adjustment, not a cancellation

    Tax-deductible amount#

    For events with a quid-pro-quo component (a $150 ticket that includes a $60 meal, for example), the deductible portion is calculated on Event_Deductible_Amount__c, a formula field on the Opportunity — so receipts and reports reflect only the tax-deductible portion of the ticket price, not the full purchase amount.
